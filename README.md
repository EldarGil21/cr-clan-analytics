# Clash Royale Clan Analytics 📊 (v1.0)

Профессиональное аналитическое веб-приложение для автоматизации управления кланом, контроля активности в Клановых Войнах (КВ) и кадрового аудита.

Инструмент спроектирован так, чтобы соруководители и глава клана могли в один клик выявлять нарушителей, оценивать боеготовность колод и отслеживать динамику развития игроков.

---

## 🗓️ Специфика Кланового Календаря (МСК)

Логика расчетов в приложении строго синхронизирована с игровыми алгоритмами Clash Royale:
* **Начало игровой недели КВ:** Каждую неделю в **Понедельник в 12:30 по МСК** (09:30 UTC). С этого момента обнуляются донаты и начинается подготовка (тренировочные дни).
* **Активная фаза Речных гонок:** С середины четверга по середину понедельника.
* **Досрочный финиш:** Если клан набирает 10 000 очков движения раньше времени (например, в субботу или воскресенье), речная гонка завершается досрочно. Приложение автоматически считывает поле `finishTime` из API и фиксирует точное время досрочного завершения.
* **Колизей:** Всегда длится полные 4 игровых дня до понедельника 12:30 МСК.

## 📋 Обзор Функционала v1.0

### 1. Текущая статистика клана
* **Детектор мертвых душ:** Автоматически выявляет игроков, которые не заходили в Clash Royale более 3 суток (на основе поля `lastSeen` из API).
* **Баланс донатов:** Показывает чистую разницу между отданными и полученными картами (`Отдал - Получил`), позволяя мгновенно ранжировать щедрых игроков.
* **Коэффициент щедрости:** Сбалансированный показатель вклада. Защищен от математических аномалий (если игрок не просил карт, коэффициент не улетает в бесконечность, а рассчитывается корректно).
* **Русская локализация:** Все технические роли Supercell автоматически переведены на русский язык (*Лидер, Соруководитель, Старейшина, Участник*).

### 2. Динамика и Надежность (Накопление истории в SQLite)
* **Индекс надежности (Consistency Score):** Уникальный показатель дисциплины игрока. Вычисляет процент недель КВ, которые участник отыграл полностью (16 из 16 атак). Требует сохранения еженедельной истории.
* **Графики активности:** Визуализируют долгосрочные тренды изменения славы в КВ и еженедельных донатов конкретного игрока.

### 3. Прогнозы и Рекомендации
* **Математическое ожидание:** На основе накопленной истории вычисляет прогнозируемую славу и донаты игрока на следующую неделю.
* **Кадровый советник:** Автоматически выдает рекомендации для руководства клана:
  * `❌ Кандидат на исключение` — при частых пропусках КВ.
  * `🎖️ Повысить до Старейшины/Соруководителя` — при стабильно высокой славе.
  * `⚠️ Предупредить` — при падении активности.

### 4. Военная разведка (Сбор досье)
* **Интерактивный радар:** Строит прогресс-бар движения всех 5 кланов вашей группы к финишу КВ в реальном времени.
* **Досье на соперников:** Фоново опрашивает API и собирает данные по каждому клану-оппоненту: их точный состав, средний уровень кубков и еженедельную активность.

### 5. Аудит прокачки и Анализ КВ-винрейта
* **Точный парсер уровней:** Переводит относительные уровни карт из API в абсолютные игровые. Корректно распознает карты **13, 14, 15 и 16 уровней**.
* **Оценка боеготовности к КВ:** Считает общее число топ-карт (14–16 уровня). Для сборки 4 сильных колод игроку необходимо минимум 32 такие карты.
* **Винрейт в КВ (Win Rate):** Анализирует последние 25 боев игрока, вычленяет только матчи КВ и вычисляет его точный процент побед.

## 🛠️ Как работать со сложной логикой

### Как рассчитываются пропущенные колоды?
Алгоритм определяет текущий день недели по МСК. Если идет КВ, рассчитывается ожидаемое количество сыгранных колод на текущий момент (День 1 = 4 колоды, День 2 = 8 и т.д.). Разница между ожидаемым значением и реальным показателем `decksUsed` записывается как пропуск. 

### Сохранение истории в базу данных
Так как облачный сервер "засыпает" при отсутствии пользователей, сохранение истории осуществляется вручную. Главе или соруководителям рекомендуется заходить на сайт **в воскресенье вечером или в понедельник утром (до 12:30 МСК)** и нажимать кнопку **«Сохранить итоги текущей недели в историю базы данных»** на первой вкладке. База данных использует колонку `clan_tag`, благодаря чему одним приложением могут пользоваться несколько разных кланов параллельно — их истории не пересекутся.
